# VOXA — منظومة التدريب الذكية ثنائية اللغة (Bilingual Luxury Training Platform)

تطبيق **VOXA** متكامل (واجهة أمامية PWA ثنائية اللغة + خادم خلفي + قاعدة بيانات علاقية مع عزل كامل للحسابات + ملف ترحيل Supabase/PostgreSQL RLS)، مبني ومطوّر انطلاقًا من فحص كامل لتطبيق `تمارين.html` السابق مع أرشفة معزولة وآمنة لبيانات `ironsys_v2`.

## 1. تشغيل التطبيق والاختبارات

```bash
# بناء الواجهة الأمامية للإنتاج (تُحفظ في public_app/)
npm run build

# تشغيل الخادم الموحد (الواجهة + الـ API + الـ PWA على المنفذ 3000)
npm start

# تشغيل حزمة اختبارات القبول الـ 15 بالكامل
npm test
```

## 2. الإعدادات الخارجية المطلوبة عند النشر الإنتاجي (Production Setup)

التزامًا بالشفافية التامة وعدم محاكاة خدمات خارجية غير مربوطة، تعمل جميع مسارات الخادم فعليًا وتفعّل المزودات الخارجية فور تزويد متغيرات البيئة التالية:

### أ. تسجيل الدخول عبر Google OAuth 2.0
المسارات `/api/auth/google/start` و `/api/auth/google/callback` منفذة بالكامل. لتفعيلها في Google Cloud Console:
1. أنشئ **OAuth 2.0 Client ID (Web Application)**.
2. أضف رابط الإرجاع: `https://<YOUR_DOMAIN>/api/auth/google/callback`.
3. اضبط متغيرات البيئة على الخادم:
   - `GOOGLE_CLIENT_ID`
   - `GOOGLE_CLIENT_SECRET`
   - `GOOGLE_REDIRECT_URI` (اختياري، يُستنتج تلقائيًا من النطاق إن تُرك فارغًا)

### ب. خدمة البريد الإلكتروني (تأكيد البريد واستعادة كلمة المرور)
تُخزّن رموز التحقق واستعادة كلمة المرور مشفرة بـ `SHA-256` في جدول `auth_tokens` بمدد صلاحية محددة.
- في بيئة التطوير الحالية (عند غياب `SMTP_HOST`)، يعرض الخادم رمز التحقق/الاستعادة محليًا بوضوح لتجربة التدفق الحقيقي.
- في الإنتاج، اربط مزود بريد (Resend / Postmark / SendGrid / Supabase Auth) بضبط `SMTP_HOST` و `SMTP_USER` و `SMTP_PASS`.

### ج. تعيين المالك الوحيد (Owner Studio RBAC)
لا يُمنح أول مستخدم يسجّل في الموقع صلاحية المالك تلقائيًا. لتعيين المالك الوحيد المخوّل بإدارة مكتبة التمارين ومراجعة تراخيص الصور:
- اضبط `VOXA_OWNER_EMAIL=owner@yourdomain.com` على الخادم، **أو**
- اضبط سرًا قويًا في `VOXA_OWNER_SECRET` واستخدم قسم «تحقق المالك» داخل الإعدادات لمرة واحدة (تُسجّل جميع العمليات الإدارية في `admin_audit_logs`).

### د. الربط مع Supabase / Lovable Cloud والنسخ الاحتياطي المجدول خارج الخادم
- يتضمن المشروع ملف `supabase/migrations/001_voxa_schema_and_rls.sql` الجاهز للتنفيذ في Supabase شاملاً سياسات **Row Level Security (`auth.uid() = user_id`)** ودالة التحقق من المالك `public.is_voxa_owner()` وقيود التحقق من مصدر وترخيص الصور المنشورة.
- يوفّر VOXA داخل التطبيق **لقطات سحابية بإصدارات (Versioned Cloud Snapshots)** مع بصمة `SHA-256` وتصدير `JSON` و `CSV` محليًا. للحصول على نسخ احتياطي مجدول مستقل خارج قاعدة البيانات (Off-site Automated Backups / PITR)، فعّل خطة النسخ اليومي التلقائي في مزود قاعدة البيانات السحابية (مثل Supabase Daily Backups / AWS S3 Cron Snapshots).
